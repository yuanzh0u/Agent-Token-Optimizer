# Portable token-efficiency core

ESM, no third-party runtime dependencies. Requires Node `>=24.16.0 <25 || >=26.1.0` for `node:sqlite` and optional `node:zlib` zstd support. Public exports are available from the package root or `/policy`, `/usage`, `/ledger`, `/discovery`, `/drift`, `/capabilities`, `/report`.

## Policy and evidence

`resolvePolicy(config, identity, capabilities = {}, host = {})` returns `{policy, provenance, scope, bindingId, effectiveMode, unsupportedReasons, softContextLimit}`. `identity` contains opaque `agentId`, `sessionId`, `runId`; optional display fields have no semantics. Binding selection matches `agentId` and optional `runId` exactly. Missing identity, unbound identity, multiple matches, or unverified enabled controls result in observation. Renaming an actual ID requires updating its explicit binding. Returned objects are fresh per call.

The strict v1 format is documented by `config/schema.json`; `validatePolicy(config)` additionally checks unique binding IDs and referenced profiles. Merge order is defaults → one bound profile → binding overrides. Controls are `mode`, `features`, `limits`, `permissions`. Features are declarations for `loopGuard`, `outputCompression`, `historyCompaction`, `pruning`, `requestGate`; this package implements no live host enforcement. Host settings such as model, skills, heartbeat, and contextEngine cannot occur in profiles. Permissions must be a subset of `host.permissions`.

`host` is `{hostVersion, runtime, provider, workClass, permissions?: string[]}`. `capabilities` is a feature-keyed map. `evaluateCapability(capabilities, feature, scope)` accepts the same four scope fields and returns `{status, reasons, evidenceRef}`. Verified evidence has `{status:'verified', scope:{hostVersion,runtime,provider,workClass}, evidenceRef:'local-evidence-reference'}`; all scope values must match exactly and be nonempty. `requestGate`/`L3` additionally needs `requestGate:true`. SDK presence alone is partial. These inputs must come from trusted host probes; an arbitrary caller-supplied label is not proof of runtime behavior.

`softContextLimit` is unknown unless limits include all of `windowTokens`, `outputReserveTokens`, `safetyMarginTokens`. It is the nonnegative window remainder, capped by optional `softContextTokens`. It is not a provider quota or a request gate. `config/profiles.json` contains four workload examples with no identity/role assumptions or installed candidates.

## Usage and sources

`normalizeUsage(raw, mapping)` returns the four nullable dimensions `uncachedInput`, `output`, `cacheRead`, `cacheWrite`, plus mapped allowlisted metadata. Provider counts must be nonnegative safe integers; missing is null. The mapping must explicitly specify both cache inclusion booleans:

```js
const mapping = {
  fields: {input:'usage.input', output:'usage.output', cacheRead:'usage.cacheRead', cacheWrite:'usage.cacheWrite'},
  inputIncludesCacheRead: false,
  inputIncludesCacheWrite: false,
  metadata: {sourceRecordKey:'id', provider:'provider', model:'model', accountId:'accountId', requestId:'requestId', agentId:'agentId', sessionId:'sessionId', runId:'runId', runtime:'runtime'}
};
```

Fields use own-property dotted paths. Metadata keys are limited to `sourceRecordKey`, `provider`, `model`, `accountId`, `requestId`, `agentId`, `sessionId`, `runId`, `runtime`, `workClass`, `timestamp`, `contentHash`; values are bounded strings. Do not map message bodies into identity fields. Provider names do not determine accounting semantics. Local character estimates cannot be supplied as provider usage.

`discoverSources({sources:[...]})` only validates explicitly configured source descriptors and returns their supported/excluded/unsupported status. It performs no filesystem discovery or home-directory scan. `collectSource(source)` is a synchronous full read-only rescan, returning `{source,status,events,cursor,reasons,excluded,fullRescan:true}`. Status is complete/degraded/unknown/unsupported/excluded. Empty or inaccessible sources do not report a successful zero.

Supported descriptors are:

```js
const jsonl = {id:'fixture-jsonl', type:'jsonl', path:'./fixtures/events.jsonl', conversationAccess:true, mapping};
const sqlite = {
  id:'fixture-sqlite', type:'sqlite', path:'./fixtures/events.sqlite', conversationAccess:true,
  table:'events', columns:{json:'event_json', zstd:'event_zstd', keys:['session_id','seq'], sessionId:'session_id'}, mapping
};
```

SQLite requires a configured table, stable key columns, and at least one JSON or zstd payload column. Keys are combined into an unambiguous JSON tuple; optional agent/session columns override payload attribution. SQLite never opens the source path. Collection uses bounded filesystem reads to read a stable rollback-journal main file, verifying unchanged inode/size/timestamps and identical bounded reads. A private 0700 temporary directory initially holds an empty O_EXCL 0600 file: SQLite opens it read-only, its name is unlinked, and fstat must confirm zero links **before** raw bytes are copied through a separate already-open descriptor. Writes handle partial progress; no raw bytes are written to a named copy. WAL-mode headers or any WAL/SHM/journal sidecars are explicitly unsupported: provide a consistent checkpointed rollback-journal snapshot. Committed live-WAL data is not silently ignored. Queries use only the already-open anonymous inode with `query_only` and a 1000ms busy timeout. Platforms that cannot open/unlink an empty SQLite file safely return unsupported before copying raw bytes, with no named fallback. File descriptors and the empty temporary directory are cleaned on handled paths; SIGKILL closes the unlinked inode through the kernel and can leave only an empty directory. Identifiers and schema columns are validated there. JSON payloads are preferred when present; otherwise zstd is decoded when this Node runtime supports it. Decode errors degrade coverage. No actual OpenClaw storage schema or cross-table session attribution is inferred.

Explicit `conversationAccess:true` is mandatory. `incognito:true` or absent/false access excludes a source. Record-level `incognito:true` and `conversationAccess:false` also exclude records. Custom record paths can be declared through `privacy:{incognitoField:'meta.private',conversationAccessField:'meta.access'}`. This cannot infer privacy stored in unrelated tables: such sources must remain excluded until a privacy-aware deployment adapter supplies the gate. No transcript fallback bypasses access restrictions.

Default source and record bounds are 64MiB and 2MiB; customize using positive safe integer `maxBytes` and `maxRecordBytes`. Collection temporarily decodes source records in memory and, for eligible SQLite files, uses an unlinked inode while the process is alive, then returns only approved usage projections and hash cursors. It creates no named raw-body copy, including for excluded incognito rows; the SIGKILL regression checks that no named raw or incognito content survives and the source directory is unchanged. Corrupt-content errors contain no raw excerpts. All fixtures/tests are local and synthetic.

## Ledger and reports

`new UsageLedger(privatePath)` owns an independent SQLite file; it must not be a source path. It creates a 0700 state directory and 0600 database, rejects symlink/unowned direct state paths, and bounds busy timeout to 1000ms. Call `close()` explicitly; repeated close is harmless. The durable schema uses application_id 1096044337 and user_version 2. Only the exact known legacy records/sources schemas at app/version 0 or owned version 1 upgrade transactionally, adding the collection_scope table without rewriting records; foreign, modified or newer schemas reject without initializing over them. Ownership preflight never opens the original path through SQLite: it checks for journal/WAL/SHM and WAL headers, streams two matching filesystem reads into a private inode opened empty and unlinked before copying, and inspects schema on that anonymous copy. Main file identity/version, sidecars and schema are rechecked at the writable boundary. Any sidecar (including cold/dangling entries), WAL-mode main or unsupported anonymous-copy platform fails closed, even for owned interrupted state. Preserve main plus sidecars and recover/validate a separate trusted copy; do not delete journals to force a retry. State requires an independent single writer; consistency checks are not an OS lock against malicious same-user races. Dangling state symlinks also reject. Back up and use separate state when downgrading.

`ingest(events,{source,cursor=null,reconcile=false,reasons=[]})` atomically commits events and cursor; it returns `summary()`. For full adapter scans pass `reconcile:true` and collector reasons. Missing old records, rewritten records, and conflicting provider/account/request copies remain quarantined, including original copies; there is no silent overwrite or automatic repair. `getCursor(source)` is diagnostic, not a reason to skip rescans. Records and counts are validated before commits, including aggregate safe-integer overflow.

Cross-source dedup requires complete `provider/accountId/requestId`, matching attribution and four known counts. Without shared IDs, only per-source totals are available. `setSourceScope(sourceIds)` transactionally persists the exact active deployment IDs, across reopen. Inactive records/cursors remain for audit and future rescan/conflict checks. `summary().sourceScope` exposes kind/activeSources/inactiveSources/inactiveRecordCount; current totals, groups, estimates and quarantine counts exclude inactive sources. Without an explicit scope, legacy/core/observer state remains `all-observations`; explicit collector scope does not automatically absorb plugin deliveries. Re-addition must be followed by a full source scan; setting IDs alone is not a freshness or provider-completeness proof. Use independent ledger/report state per deployment.

`summary()` returns `perSource`, exact attribution `groups` (including provider and model), `global`, `globalComplete`, `coverage`, `quarantined`, and `localEstimates`. Aggregates have `eventCount`, nullable `totals`, `knownTotals`, `knownCounts`. Complete global totals are null when coverage is incomplete. Source coverage reasons or quarantined records make that source's and its groups' totals null; known partial values remain under knownTotals/knownCounts. Unaffected sources retain their own complete totals. Unknown agents get independent source/record buckets. Optional event `localEstimates` accepts the four nullable dimensions and is never merged into actual usage.

`await writeReport({directory,collect:()=>ledger.summary(),now?,staleAfterMs?})` publishes private local `report.json` and `report.html`; `readReport(directory,{now?,staleAfterMs?})` returns freshness and snapshot, using the validated saved staleness threshold unless explicitly overridden; `renderReportHtml(snapshot)` escapes all labels. Reports project only approved statistics, discard other fields, and never include exception messages. Before collection, a private `collection-health.json` records collecting; failed collection preserves both previous snapshot files byte-for-byte and records failed health. Successful JSON/HTML publication alone may mark healthy, bound to the snapshot publicationId. `readReport` (and CLI in another process) remains stale on failed/collecting/missing/corrupt/unmatched health until a successful recovery publication. Health contains only schema/status/time/publication ID, and participates in ownership, symlink/hardlink and deployment alias guards. Legacy snapshots without health are conservatively stale. Saved HTML recomputes only snapshot age and explicitly cannot observe later collection failures; use CLI/readReport for current durable health. All three saved files must be retained together. A health write failure stops collection before sources are read; no power-loss fsync or concurrent-writer guarantee is implied. There is no reporting network transport.

## Config changes

`fingerprint(config)` hashes canonical private JSON including secret changes. `redactConfig(config)` returns a public snapshot with sensitive key values (including accessKey/privateKey spelling variants) and whole URLs containing userinfo or named credential query parameters hashed. `planPatch(config,[{path:['plugins','example'],value:{enabled:true}}],baseHash)` returns `{config,receipt}` without writes. Use `{path:[...],unset:true}` to remove a key. Paths must be non-overlapping, safe own-property string keys; nested parents must exist.

`rollbackPatch(current,receipt)` restores only owned keys after checking their expected patched state; later independent edits survive, while changed owned keys or removed parents reject rollback. Unset versus explicit legacy/custom engine states are preserved. Receipts contain private before/after values for restoration and must be stored as sensitive 0600 data; never put them in public snapshots/reports. No entire configuration restore is performed.

The offline suite validates only portable contracts. It establishes no installed-host capability, candidate plugin result, real-model usage, quota guarantee, monetary savings, or soak result.

## Controlled offline experiments

Additional root/subpath exports: `/test-controller`, `/experiment-contracts`, `/replay`, `/evaluate`. These APIs supply injected seams, contracts and arithmetic. They do not select plugins, install candidates, change a context engine, call a model, or establish host enforcement. A trusted integration must route **every** primary, retry, summary, retrieval and fallback provider call through the controller. Calls outside that integration remain unsupported/partial.

`createTestController({provider,usageMapping,limits?,externalPaths?})` returns `{request,report,cancel,drain}`. Defaults: concurrency 1, 20 requests, 500000 cumulative estimated input tokens, 1024 maximum output tokens per request, 600000ms wall time. All limits are positive safe integers. `request(input,{estimatedInputTokens,purpose?,signal?,onChunk?})` requires a nonnegative safe integer estimate, including an explicit zero if applicable; absent/unknown estimates reject before provider entry. Purpose is primary/retry/summary/retrieval/fallback. Reservations consume the estimated admission budget before invoking the provider and are not refunded on failure. Waiting requests reserve when a concurrency slot becomes available. The first count/estimated-budget violation closes admission for the entire controller.

The injected provider signature is `provider(input,{signal,maxOutputTokens,purpose})`. Its trusted adapter must translate and honor the output limit for its provider; no provider-specific fields are guessed or overwritten. Provider return values and exceptions use the explicit core `normalizeUsage` mapping. Async iterables are consumed to settlement; optional `onChunk` receives each chunk, and `request` resolves to the final chunk. Stream usage fields must be **cumulative snapshots**, not token deltas. A throwing/rejecting `onChunk` rejects the caller and disables further callback delivery, while the provider stream continues draining/accounting and retains its concurrency reservation until settlement. Delivery failure counts as a failed caller request; a subsequent provider settlement is late. A transport error or cancellation makes stream usage explicitly incomplete: `measured` stays null and `usageComplete` stays false, while the latest observed cumulative counts remain under `knownMeasured`. Normal local iterator exhaustion after abort does not establish remote billing completion. Missing chunks do not erase a prior usage snapshot; invalid counts make the request's usage unknown. The report projects usage only, with known partial totals separate from nullable complete totals, estimates, overshoot and content-free start/end/cancel trace events.

Any request cancellation, explicit cancel, deadline, or exceeded admission limit rejects new/queued work, signals active providers, and promptly rejects active caller waits. An uncooperative provider can remain active indefinitely and incur usage; its later settlement remains observed and counted. `drain({timeoutMs:1000})` bounds waiting for all active/queued work and reports what is still pending. A timeout never invents zero usage or frees a still-active slot. This is an estimated test budget, **not a hard token/billing cap**. In-process asynchronous timers cannot preempt synchronous blocking provider/candidate JavaScript. Default reports retain no request, response, chunks, tool output, commands, or exception text.

`executeWithOutputProcessor({execute,toolKind,exact?,critical?,candidate?,requiredFacts?,timeoutMs?})` executes a tool once and returns `{result,audit}`. Its result schema is `{text:string,exitCode:integer}`. Only `toolKind:'shell'` is eligible; exact reads, read tools, JavaScript, Code Mode and unknown kinds pass through. Candidate is one `{name,kind:'actual-candidate'|'mock',process(originalClone)}`; supplying an array rejects before tool execution. No candidate means untested/pass-through. The adapter supplies no compressor. Exceptions, bounded asynchronous timeouts, empty/invalid text, changed exit status, and missing required literal facts fall back to the saved original result. Required facts must exist in both original and candidate text; this is a caller-provided fidelity oracle, not semantic proof. Extra semantic/ordering/structured-data checks remain the candidate's test responsibility.

Before altering critical evidence, the candidate must provide `recovery:{handle,read()}`; the harness calls `read` under a timeout and verifies that the recovered text and exit status match the original. The handle is an opaque nonempty bounded reference. A claimed reference without a working reread fails closed to original output. Recovery adapters must read stored raw output and must never reexecute the original command. Audits retain only counts/booleans/reasons, never output or the recovery handle. The harness's bounded wait cannot stop candidate code from doing external work; use only trusted isolated candidate adapters.

`validateHistoryContract({originalHistory,candidateHistory,engineOwners,originalEngine,selectedEngine,requirements?,citations?})` checks one owner, unchanged engine selection, complete ordered tool call/result pairs, literal current requirements and citations. Messages use `{role,content?,toolCalls?:[{id,name}]}` and tool responses use `{role:'tool',toolCallId,content?}`. These are explicit fixtures rather than inferred native transcript formats. No input is modified. `evaluateHistoryLifecycle({fixtures})` returns contract-only stage results and keeps actual Lossless T13–T16 pending. It supplies no summary engine, migration, original-history rewrite or runtime lifecycle proof.

`replayToolCalls({calls,adapter?})` accepts inert fixture records `{sessionId,runId,tool,args?,progress?,timestamp?,outcome?,sideEffect?}`. Each session/run pair gets independent state. Adapter is `{kind:'actual-native'|'mock',evidenceRef?,create({sessionId,runId})}`; create returns `{inspect(call),record(call)}` and inspect returns `{blocked:boolean}`. Actual-native adapters require an evidence reference. **The caller authenticates that adapter's provenance**; a label alone is not evidence. Native private functions may be imported by an explicit isolated probe outside this package, but are never a runtime dependency. Replay never calls a fixture's execute function or performs its side effects. Counts are modeled invocations; reaching a block terminates further modeled invocations within that boundary. Errors mark coverage partial. No adapter yields not-tested. `createMockDetectorAdapter({threshold:3})` is a deliberately simple reference mock using tool/args/progress, ignoring timestamps; it is neither copied native logic nor a production loop guard.

`evaluatePairedResults(dataset,{verifyEvidence?,verifySoak?,now?})` evaluates one fixed task/model/thinking/cache/workload stratum across paired runs. Each pair has a unique id and baseline/candidate. Each run supplies `{stratum:{task,model,thinking,cache,workload},sourceKind:'provider-measured',coverage:'complete',expectedRequests,success,criticalFacts,sideEffectCount,latencyMs,requests}`. Requests have unique `evidenceRef`, `purpose`, `status:'success'|'failed'|'cancelled'`, and a canonical four-dimensional `usage` from core normalization. Include every failed/retried/summary/retrieval/fallback request, not only the successful final attempt. `expectedPairCount` and `expectedRequests` must match all supplied samples. A trusted source adapter must verify completeness against its ledger; this evaluator cannot detect omitted calls if supplied counts and an untrustworthy verifier both lie.

Numeric JSON and `sourceKind` labels never establish real measurement. `dataset.synthetic:true` always prohibits claims. Actual evidence requires `synthetic:false` plus a trusted **synchronous** `verifyEvidence(request,run,pair,arm)` returning exactly true for every provider record; default verification rejects. An injected verifier is a trust boundary and must authenticate actual source records and their usage, not return true for arbitrary labels. Tests use fictional counts with a trust stub only to validate eligibility arithmetic and do not publish them as experimental gains.

The dataset also supplies `heldout:{independent:true,untuned:true,evidenceRef}`. Five pairs qualify for screening; at least twenty complete verified pairs and independent untuned heldout selection are required for a claim. Missing/null/invalid usage, mismatched strata, missing samples/latency, critical-fact or success regression, changed side effect counts, or >20% nearest-rank P95 latency degradation prohibit claims. Failure pairs remain included. Unpriced results permit only vector improvement: all four totals nonincreasing and at least one decreasing. Optional pricing is `{currency:'USD',perMillion:{uncachedInput,output,cacheRead,cacheWrite}}` with finite nonnegative prices for every dimension. Empty/zero baselines have null/N/A ratios. Pricing cannot bypass quality/coverage gates. `savingsRate` is a fraction and stays null without eligible pricing.

24/48/72h `soakGates` remain pending by default. Evidence entries `{startedAt,endedAt,passed:true,evidenceRef}` must demonstrate actual elapsed milliseconds, end no later than `now`, and pass independent `verifySoak(evidence)`. Passing elapsed gates alone never marks rollout/adoption ready.

Runnable offline examples from the repository root:

```sh
node scripts/token-efficiency-test-controller.mjs
node scripts/token-efficiency-replay.mjs tests/fixtures/token-efficiency/replay.json
node scripts/token-efficiency-replay.mjs tests/fixtures/token-efficiency/replay.json --mock
node scripts/token-efficiency-evaluate.mjs tests/fixtures/token-efficiency/paired-synthetic.json
```

The first command runs a fake-provider contract probe only; it has no real-provider flag. The other commands default to not-tested/unverified evaluation. Replay may explicitly load a trusted local `--adapter module.mjs` exporting `adapter`; evaluation may explicitly load `--evidence-module module.mjs` exporting synchronous `verifyEvidence` and optionally `verifySoak`. JSON input never selects executable modules. These modules are trusted code, not a sandbox. The package does not require any `/tmp` candidate artifact or absolute installed-host path. Candidate activation, actual Lossless lifecycle, real paired model results, monetary savings and elapsed rollout evidence remain pending.

## Root integration distribution

The root `agent-token-optimizer` distribution contains this core, the portable CLI and the thin OpenClaw observer in one tarball. `src/collector.mjs` exports `loadDeployment(path)` and `collectDeployment(path)` via the root `/collector` export; paths are relative to the deployment file, aliases are rejected before writes, incomplete scans do not reconcile, and all-source failure retains a stale report. The nested observer package is private and must not be distributed alone. CLI/core do not import the host SDK; only the TS plugin entry does. `writeReport({synthetic:true,...})` labels offline fixture snapshots as synthetic with zero real model requests; it is a caller provenance declaration, not authentication of arbitrary data.
