# README and repository discovery

The public homepage identifies the project in text, uses task-oriented headings, documents installation and expected outcomes, links to evidence, and states the preview boundaries. English and Chinese entries link to one another. Repository description/topics express actual capabilities. The agent installation contract is a convenience for operators, not an indexing prerequisite.

No ranking, indexing or AI-citation guarantee is made. There is no keyword-stuffed hidden text, fabricated savings metric, or unsupported npm-install claim. GitHub controls the rendered page and its head metadata; this repository does not pretend that a README can install custom site-wide SEO tags.

Primary guidance consulted on 2026-10-22:

- [GitHub: About repository READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes): project purpose, getting started, support and maintainers; usable headings and relative documentation links.
- [GitHub: Repository topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics): descriptive topics in the supported format and limit.
- [Google Search: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features): ordinary search best practices remain relevant; no special AI text file or schema is required.
- [Bing Webmaster Guidelines](https://www.bing.com/webmasters/help/bing-webmaster-guidelines-30fba23a): discoverable, accurate, well-structured content supports search and grounding eligibility without guaranteeing inclusion.
